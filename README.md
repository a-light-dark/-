# 校园圈小程序

一个用「微信原生小程序 + 云开发」做的校园社区论坛。功能结构参考了校园社区类小程序，但入口、交互和配色都有我们自己的调整，所有内容均为通用校园场景。

## 数据是怎么走的

页面**只调用** `miniprogram/utils/api.js`，它内部做两件事：

- 云开发可用 → 读写云数据库（`posts` / `comments` / `orders` / `users` / `likes` / `favorites` / `reports` / `notices`）
- 云开发不可用（云函数没部署、登录失败）→ **自动退回** `utils/mock.js` 的本地演示数据

所以就算云开发还没配好，界面也点得动；配好之后不用改页面，自动就是真数据。首页底部会提示「当前是本地演示数据」，看到它就说明云端还没连上。

## 云开发配置（当前环境）

- 环境 ID：`cloud1-d6g26wz61eca836b8`（已写进 `miniprogram/app.js` 的 `CLOUD_ENV`）

| `users` | 用户资料（nickname/avatar，首次登录自动创建） | 自定义规则：只读 |
| `likes` | 点赞记录（postId，一人一帖一条） | 自定义规则：只读 |
| `favorites` | 收藏记录（postId，一人一帖一条） | 仅创建者可读写 |

| `feedback` | 建议反馈（content/contact/nickname/avatar/status 待处理·已处理） | 所有用户不可读写 |

| `wordfilters` | 敏感词库（word，圈主后台维护，发帖/评论/悬赏先本地拦截） | 所有用户不可读写 |
| `backups` | 备份记录（fileID/size/createdAt，圈主一键导出数据 JSON 到云存储） | 所有用户不可读写 |

> `favorites` / `reports` / `notices` / `feedback` / `follows` / `reviews` / `announcements` / `bans` / `settings` / `audit_logs` / `trash` / `wordfilters` / `backups` 是后加的，不用手动建：调用一次 `setupCollections` 云函数就会建好（在开发者工具里给云函数发个空参数即可，已存在会跳过）。

- 云函数部署：左侧 `cloudfunctions` 下右键每个文件夹 → **「上传并部署：云端安装依赖」**（23 个都要）
- 云存储：头像存 `avatars/<openid>/时间戳.png`，帖子图存 `posts/<openid>/时间戳-随机数.png`；云开发控制台 → 存储 里能看到（免费额度够用）
- ⚠️ **云存储权限必须是「所有用户可读，仅创建者可读写」**（控制台 → 存储 → 权限设置）。如果不是，别人帖子的图片会显示 `STORAGE_EXCEED_AUTHORITY` 加载不出来。列表里的图片客户端会先用 `getTempFileURL` 换成临时 https 链接再显示，真机上更稳
- 发帖图片：客户端先压到 quality 70 再上传；云函数校验「必须是自己传到 `posts/<openid>/` 下的文件」，并逐张做图片内容检测（同步接口单张上限 750KB）

## 内容安全（发帖/评论/昵称都会查）

同一用户每 60 秒最多发 5 篇帖子、10 条评论、3 个悬赏、5 次举报、3 条反馈。各入口独立计数，达到上限时提示剩余等待秒数。

UGC 小程序必须过内容安全审核，否则正式上线会被打回。现在所有「用户写的文字」都在云函数里过一遍 `security.msgSecCheck`：

| 入口 | 走哪个云函数 | scene |
|---|---|---|
| 发帖 | `createPost` | 3（论坛） |
| 发悬赏 | `createOrder` | 3（论坛） |
| 发评论 | `addComment` | 2（评论） |
| 删自己的评论 | `deleteComment` | 校验作者；删顶层评论会把它下面的回复一起删，并把 `posts.commentCount` 减回去 |
| 改昵称 | `updateProfile` | 1（资料） |

- 判定为 `pass` → 正常入库；`review` / `risky` → 直接拒绝，前端 toast 提示「内容可能不太合适，换个说法再试试」
- 图片检测走 `security.imgSecCheck`：云函数把图从云存储下载下来再送检，单张同步接口上限 750KB，超了直接拒绝；违规时连刚上传的图片一起删掉
- **头像也要过图片检测**：`updateProfile` 会把 `avatars/<openid>/` 下的头像下下来送检（客户端先压到 quality 70），违规就删掉那张图并提示「头像不太合适，换一张试试」
- 云函数默认超时只有 3 秒，图片检测加了 1.5 秒超时保护（超时先放行 + 打日志）。**正式上线前建议**去 云开发控制台 → 云函数 → `createPost` → 配置，把超时时间调到 20 秒
- 昵称和头像由云函数从 `users` 里读，客户端传上来的参数只当兜底，防止伪造
- 云函数用 `cloud.openapi` 必须在函数目录的 `config.json` 里声明权限，否则会报 `-604101`（我们已经踩过）：

```json
{ "permissions": { "openapi": ["security.msgSecCheck"] } }
```

- 检测接口本身出错（超频/网络）时会先放行并打 `console.warn`，不让整个发帖功能瘫掉；上线前可在 云开发 → 云函数 → 日志 里查这类告警。

## 收藏 / 删帖 / 举报

| 功能 | 谁来做 | 说明 |
|---|---|---|
| 收藏 / 取消收藏 | 客户端直接写 `favorites` | 集合是「仅创建者可读写」，一人一帖一条；详情页按钮状态从集合里读，重启后还在 |
| 我的收藏 | `pages/favorites` | 按收藏时间倒序，最多 30 条；点卡片进详情 |
| 删除自己的帖子 | `deletePost` 云函数 | 服务端条件删除（`where({_id, _openid})`），不是作者就返回「只能删自己发的帖子」；连带清掉评论/点赞，**并把云存储里的图一起删掉**（返回 `filesRemoved`）；收藏记录故意保留，别人收藏里会显示「帖子已被删除」 |
| 举报别人的帖子 | `reportPost` 云函数 | 理由白名单 + 同一个人重复举报不重复记；不能举报自己的帖子 |
| 编辑自己的帖子 | `updatePost` 云函数 | 只能改正文和话题，**图片保持原样**；服务端校验身份 + 再过一次 `msgSecCheck`（违规就不给保存）；改完首页/详情自动刷新 |

详情页底部会根据帖子归属显示「编辑 / 删除这条帖子」（自己的）或「举报」（别人的）。点「编辑」会跳到发帖页并带出原文和已选话题，保存后回原页刷新。

| 删除被举报的帖子 | `adminReview`（`action:'deletePost'`） | 服务端删帖，并连带清掉 `comments` / `likes` / `favorites` / `reports` / `notices` 里跟它有关的数据 |

| 触发 | 谁写 | 通知谁 | 文案 |
|---|---|---|---|
| 有人评论你的帖子 | `addComment` | 帖子作者（不是评论人自己） | 「评论了你的帖子：xxx」 |

> 测试时可以用 `setupCollections` 云函数塞一条「别人发来的」通知：传 `{ seedNotice: { toOpenid: 你的openid, type: 'like', postId: '帖子id' } }`，清理时传 `{ removeNoticeId: '通知id' }`。
>
> 消息页顶部有分类 tab（全部 / 评论 / 点赞 / 订单），是在本地对已拉取的 50 条做筛选，不额外请求；点 tab 后空态文案也会跟着变。

## 评论（楼中楼）/ 浏览量 / 排序

**楼中楼**：评论下面可以再回复，回复挂在被回复的那条评论下面，而不是平铺：

| 场景 | 行为 |
|---|---|
| 直接评论帖子 | 到评论区最上面（平铺） |
| 点某条评论的「回复」 | 输入框上方出现「回复 @昵称」提示，发出去挂在那条评论下面 |
| 回复一条「回复」 | 统一挂到同一条顶层评论下面（都是两层级，不再往下嵌套） |
| 「N 条回复」 | 顶层评论右下角，点开在下面展开/收起 |

- 数据结构：`comments` 文档多了 `parentId`（顶层评论的 id）和 `replyTo`（被回复人的昵称）；没有 `parentId` 就是顶层
- 读取：`api.fetchComments` 一次性取 100 条，`buildCommentTree` 在本地拼两层（顶层按时间倒序，回复按时间正序；父评论被删的回复会自动降级成顶层，不会消失）
- 通知：有人回复你的评论，通知发给你（不是帖子作者）；`addComment` 写 notices 时按「有 parentId 就通知被回复人」处理

**浏览量**：详情页现在走 `postDetail` 云函数，一次请求返回「正文 + 点赞/收藏状态 + 第一页评论（默认 30 条）+ 详情页底部广告」，服务端同时给 `posts.views` 原子 +1；同一个人 5 分钟内看同一条帖子只计一次（客户端节流）。评论超过 30 条时，滑到底会自动再取下一批（`withPost:false`，只查评论，不再重复查帖子/广告），底部会显示「上拉加载更多评论 / 没有更多评论了」。详情页统计行是「👍 点赞 / ⭐ 收藏 / 👀 浏览 / 💬 评论」。

**排序**：首页帖子流上方有「最新 / 最热 / 浏览」三个 chip。

- 最新：按 `createdAt` 倒序
- 最热：按 `likeCount` 倒序
- 浏览：按 `views` 倒序

> 帖子多了以后建议在云开发控制台给 `posts` 建三个降序索引：`createdAt`、`likeCount`、`views`（名字随意，比如 `idx_created_desc` / `idx_like_desc` / `idx_views_desc`），避免全表扫描。

## 互助订单流程（双向确认 + 收益）

订单有五种状态，全部由 `grabOrder` 云函数用「条件更新」流转（改状态时带上前置条件，防止两个人同时抢/乱改）：

```
待接单 ──抢单(接单人)──▶ 已接单 ──标记完成(接单人)──▶ 待确认 ──确认完成(发布人)──▶ 已完成 ✅
   │                        │
   └──撤销(发布人)──▶ 已撤销   └──取消接单(接单人)──▶ 回到待接单
```

- 抢单前会弹确认框（显示金额），不会「点一下就直接接走」
- 接单人标记完成 ≠ 真完成：要等**发布人确认完成**，这一步之后才计入收益（单方面点完不算数）
- 互助大厅点整张订单卡进订单详情页（`pages/order/order`）：双方昵称、金额、状态流程一目了然，按钮按身份显示——发布人可撤销（仅没人接时）/确认完成，接单人可标记完成/取消接单
- 我的收益（「我的」→ 我的收益 → `pages/earnings/earnings`）：我接的、已完成且对方确认过的订单，显示累计金额 + 明细

## 合规与隐私（提审必备）

注销会清理本人关注、本人提交的反馈，以及本人给出和收到的订单评价。返回的 `deletedFollows`、`deletedReviews`、`deletedFeedback` 是本次实际删除条数。审计日志和安全告警按审计留存要求保留。

正式上线（企业主体 + 「社交-社区/论坛」类目）审核会看这些，已经补齐：

| 项 | 位置 | 说明 |
|---|---|---|
| 用户协议 | `pages/agreement/agreement` | 服务内容、账号身份、发布规范、内容审核、互助免责、协议变更与终止 |
| 隐私政策 | `pages/privacy/privacy` | 收集哪些信息（openid / 昵称头像 / 帖子图片 / 点赞收藏）、用途、存储与保护、你的权利（查看·删除·注销） |
| 社区规范 | `pages/rules/rules` | 鼓励什么、禁止什么、互助规矩、违规怎么处理 |
| 注销账号 | `pages/account/account` | 说明会删哪些数据，二次确认后调 `deleteAccount` 云函数真删 |
| 隐私提示弹窗 | `pages/index/index` | 首次启动弹「用户隐私保护提示」，同意后把 `privacyAgreed` 写进本机 Storage，不再打扰 |

- 注销是**真删数据**：`deleteAccount` 云函数依次清 `posts`（连同它的评论/点赞/收藏/通知/举报）→ 自己在别人帖子下的评论（并把对应帖子 `commentCount` 减回去）→ 点赞（`likeCount` 减回去）→ 收藏 → 通知（发给我的 + 我发出的）→ 举报记录 → `users` 里的资料
- 有进行中的互助订单（自己是发布人或接单人）时**不允许注销**，会提示先处理完，避免订单里的另一位同学数据错乱
- 弹窗是自研的（没依赖微信官方 `agreePrivacyAuthorization` 接口），审核足够用；要改用官方隐私授权能力，在这套 UI 上换按钮类型即可
- 页面正文里写着「体验版示例文本」，正式提审前把运营主体名称、联系邮箱替换成朋友公司的信息

## 流量看板 / 广告位 / 屏蔽词命中（管理后台）

工作台今日计数及看板的 7／14／30 天趋势按北京时间零点分日。每次请求工作台时刷新今日帖子和评论数。趋势返回完整日期 `key` 和用于图表显示的 `day`（MM-DD）。

- **流量看板**（Web 后台 / 小程序管理台同数据）：近 7/14/30 天新增帖子、评论、同学柱状图；帖子总数 / 浏览总量 / 点赞 / 互助单 / 活跃同学（7 天内发过帖或评论）；浏览最多、点赞最多 Top5；话题分布。数据来自 `adminApi` 的 `analytics.overview`（扫最近 1000 条聚合，不额外花钱）。
- **真实 UV/PV 不在云开发里**：微信小程序后台 → 统计 → 访问分析，才有启动次数、访问人数、留存；本页是「内容与互动流量」。
- **广告位**：集合 `ads`（24 个集合之一），字段 `title/image/position/linkType/linkValue/weight/enabled/startAt/endAt/views/clicks`。位置 `home_banner`（首页 banner，已接入小程序首页）和 `detail_bottom`（详情页底部，已接入帖子详情页，0.6.18）。管理台「广告管理」负责增删改、开关、看曝光/点击/点击率。
- **广告下发接口**：`siteData`（公开云函数）返回 `ads` 数组，只给 `enabled=true` 且在投放时间窗内、按 `weight` 倒序；小程序端 `api.fetchSiteData()` 拿到的 `ads` 已把云存储 fileID 换成临时 https 链接。
- **曝光/点击上报**：`siteData` 的 `adReport` 动作（`{action:'adReport', id, type:'view|click'}`），小程序端 `api.reportAd(id, type)` 封装；首页加载时曝光一次、点广告时点击一次。
- **屏蔽词命中**：`wordfilters` 每个词多了 `hits`/`lastHitAt`；`createPost`/`addComment`/`createOrder` 命中时自动 `inc(1)`。Web 敏感词库支持「批量导入（一行一个/逗号分隔，单次 ≤100）」「复制全部」「按命中次数排序」，能直接看出哪类内容最常被拦。

## 数据库与性能

集合清单、索引该建哪些、时间字段为什么必须存 `Date`、查询该守的几条规矩，以及这轮优化前后的实测数字（首页 225→21 次读、榜单 400+→1 次调用等），都写在 [`docs/database.md`](docs/database.md)。

顺手做的两件事：

- `board` 云函数：本周榜单从「客户端拉 100 条帖子 + 200 条评论」改成服务端算完只回 10 条，60 秒缓存。
- `maintain` 云函数：发现历史数据里 `createdAt` 混进了 ISO 字符串（会让「今天/最近 7 天」的范围查询直接失效），已批量转成 `Date`（46 条文档、0 失败）；以后再遇到用 `tcb fn invoke maintain --params '{"action":"scan","token":"<后台 token>"}'` 先抽样（该函数现在只认后台登录 token，普通用户调不动）。
- 后台列表不再查总数：举报 / 帖子 / 建议反馈三页原来是「先 `count()` 全表扫一遍再取一页」，条数多了等于每次翻页都交两份钱。现在改成「多取一条判断有没有下一页」（`hasMore`），分页器只显示上一页/下一页，首屏少一次全表 count；工作台那 8 个 KPI 仍然保留 30 秒缓存。

## 备份 / 恢复、安全告警、冒烟脚本

- **备份**：后台「数据备份」→「立即备份」，把 20 个集合导成一个 JSON 存云存储（`admin_sessions` 故意不备份，token 不该进备份文件）。
- **恢复**：同一页点「恢复」→ 先试算（只统计每个集合多少条）→ 确认后按文档 `_id` 覆盖写回。云函数一次最多跑 3 秒，所以网页会自动分批发（每批 50 条、并发 10），几十条到几千条都能恢复；`_openid` 写不进去时会退一步保留原归属。
- **安全告警**：`msgSecCheck` / `imgSecCheck` 出错时我们是「先放行」的，以前只打日志。现在每次放行都会写一条到 `security_alerts`，后台「安全告警」页能按文字/图片筛选，看错误码和触发内容。
- **冒烟脚本**：`node tools/smoke.js` 会用 tcb CLI 依次调 6 条关键链路（后台登录、工作台统计、安全告警、首页聚合、搜索、详情页），全绿说明线上没坏。

## 实时红点、热搜词、在线设备（P3）

- **实时红点**：`app.js` 里对 `notices` 开了 `watch`，别人给你评论/点赞/抢单时一变更就推送，不需要等轮询；监听失败会自动退回「每分钟查一次」。它依赖 `notices` 的安全规则是「只能读发给自己的」——**这条规则已经配好了**（2026-11-18 用 `tcb api tcb ModifySafeRule` 写入）：

```json
{"read": "doc.toOpenid == auth.openid", "write": false}
```

> 副作用（设计如此）：客户端读 `notices` 时必须带 `toOpenid` 条件，否则会被判「无法证明安全」而拒绝。以后自己加查询记得带上。

- **热搜词**：搜索页的「热门搜索」不再是写死的 8 个词，而是 `search_hot` 集合按搜索次数排的真实榜单（每次搜第 1 页 +1），不够 8 个时用默认词补位。
- **在线设备**：后台「账号管理 → 在线设备」能看到所有未过期的登录会话（账号/身份/登录时间/到期时间），点「强制下线」立刻让那台设备的 token 失效（15 秒内），适合「手机丢了 / 借人登录过」的情况。

## 和参考模板不一样的地方（我们自己的设计）

1. 主色用微信绿 `#07c160`，不用模板的蓝色。
2. 分类入口换成：跑腿代取 / 学习搭子 / 失物招领 / 脱单交友；点一下就是按话题真筛选，再点一次取消，不是摆设。
3. 板块 tab 会真的按话题筛选帖子，不是摆设。
4. 发帖支持「匿名发布」，昵称显示为「匿名同学」，适合树洞。
5. 帖子详情页加了「收藏」按钮，收藏记录真正存进数据库，并有「我的收藏」列表页。
6. 今日热榜按点赞数取第一名，不是写死的。
7. 抢单用云函数做条件更新，两个人同时抢只有一个人成功。
8. 自己的帖子能删（连带清评论/点赞），别人的帖子能举报（理由白名单 + 防重复举报）。
9. 消息中心是真的：评论、点赞、抢单都会通知到人，未读红点 + 一键已读，点一条直接跳到对应帖子/大厅。
10. 搜索能搜内容、昵称、话题，还带热门搜索词和本机搜索历史；「我的」里能翻自己发过的帖子和评论。
11. 举报不是「只记录」：圈主在「我的 → 举报处理」里能看举报列表、核对原文、一键删帖或忽略，不用进控制台。
12. 订单是双向确认的：抢单有确认框、完成要发布人确认，发布人能撤销没人接的悬赏、接单人能取消接单，收益只算「双方确认完成」的订单——不是单方面点一下就完事。
13. 每个话题都有独立页面（点帖子上的 #标签 就进），顶部是话题介绍和「参与话题」入口；首页「🏆 榜单」里能看本周热帖 Top5 和活跃同学 Top5。
14. 社区有「人」的维度：点任何人头像能进他的主页（帖子 / 被赞 / 评分），话题能关注并在首页单独筛，订单完成后能互评——评价会挂到对方主页上，不是只弹个 toast。
15. 长按就能处理内容：帖子正文长按「复制 / 举报 / 删除」，评论和回复长按「复制 / 回复 / 删除」（删顶层评论会连它下面的回复一起删并回补评论数），消息长按「标为已读 / 删除」——不用翻到页面角落找按钮。

- 集合权限已按自定义规则收紧（`posts` / `users` / `comments` / `likes` / `orders` 只读）；新增的 `reviews` 记得同样设成「所有用户不可读写」，`follows` 保持「仅创建者可读写」。
- 「我的」页统计只取前 100 条帖子，超过会少算。
- 管理员白名单写在云函数里，加人需要改代码重新部署（正式运营可以改成 `admins` 集合或后台配置）。
- 收藏里被删的帖子会一直留着占位卡片，直到本人点一下移除（故意的，不再偷偷删记录）。
- 话题上限统一成 5 个（新建/编辑一致，服务端按白名单过滤）；老帖挂了 5 个以上话题时，编辑保存只会保留前 5 个。
- 消息通知没有实时推送：要进「消息」页或 App 回到前台才会刷新；列表已支持上拉翻页（每页 20 条）。
- 订单评价是一次性的：评完不能改、不能删；评分是「别人给我的平均分」，自己给自己的不算；只有双方都是「已完成」状态才能评，所以如果对方一直不确认，这单就评不了。
- 「活跃同学」是按昵称聚合的：两个人都叫「同学」会被合并成一个（要更准就得给每人都建稳定 ID，先记着）。
- 话题页/榜单都是「取最近 N 条在本地算」：话题页最多 50 条帖子，榜单只统计最近 7 天、最多 200 条帖子和 200 条评论。
- 图片能不能被别人看到取决于云存储权限（要设成「所有用户可读」），客户端已经换成临时 https 链接加载，但权限不对时依然会加载失败。
- 楼中楼只做两层：回复「回复」时会挂到同一条顶层评论下面，不继续往下嵌套（好处是不会出现很深的缩进，坏处是「A 回复 B 的回复」看不出对谁说的，只显示被回复人昵称）。
- 浏览量是「客户端调用 + 服务端原子 +1」，同一人 5 分钟节流只在客户端记（换设备/重新进入会重新计一次）；没做防刷，量大了再补。
- 首页热门/浏览排序依赖 `posts` 的 `createdAt` / `likeCount` / `views` 索引，没建索引时帖子多会变慢（控制台建三个降序索引即可）。
- 消息分类 tab 已经是服务端按类型分页查询（每页 20 条，可上拉加载）；未读数始终是「全部未读」，与当前 tab 无关。
- 删评论不会回头清理它引发的那条通知：通知点进去会提示「内容已经删掉了」（通知保留是为了让「谁回复过你」有迹可循）。




## 压测与容量（实测数据）

场景：用云函数 `setupCollections` 的压测辅助批量造数据，再逐项测接口和页面加载耗时（开发机 + 真实云环境，数值包含网络往返；冷启动会明显偏高）。

| 数据量 | 测的东西 | 结果 |
|---|---|---|
| 300 帖 / 600 评论 / 600 消息 / 80 举报 / 60 反馈 | `posts.list` 第 1 页（冷） | 1.9 s |
| 同上 | `posts.list` 第 10、15 页 | 0.5 s |
| 同上 | `posts.list` 关键词搜索（扫 300 条） | 0.5 s |
| 同上 | `reports.list` 分页（20/页） | 0.6–0.7 s |
| 同上 | `feedback.list` 分页 | 0.4–0.6 s |
| 同上 | `notices` 首屏 bundle（列表 + 未读数 + 总数） | 0.9 s（冷 2.2 s） |
| 同上 | 消息页第 2 页 / 帖子页第 2 页 | 0.7–0.8 s |
| 同上 | 管理台仪表盘（8 项统计） | 0.8 s |
| 小数据（几十条） | 管理台各页首屏 | 0.4–0.7 s |

结论：
- 几百到一千条量级，现有「云函数排页 + 上拉加载」扛得住，页面 1 秒左右能出第一屏；冷启动第一次调用会 1–2 秒，属于正常。
- 慢点主要在**云函数冷启动**和 **orderBy 排序**；`posts` 的 `createdAt` / `likeCount` / `views` 三个降序索引要建好，消息集合建议再建 `toOpenid + createdAt` 复合索引（控制台 → notices → 索引管理）。
- 真正上千条以后，列表一定要分页、不要一次拉全量；`fetchPosts` 系列已经限制每页 10–20 条。

## 数据库成本优化（版本号 / 首页合并请求 / 词库单文档）

发帖、评论和互助匹配屏蔽词时会统一全角 ASCII 和大小写，并忽略空白与零宽字符。后台按归一化后的词去重，保留原词用于展示和命中统计。

云开发按「文档读次数」计费，小程序早期版本有几个热点很不划算，这一轮统一收拾了：

| 场景 | 改之前 | 改之后 |
|---|---|---|
| 发帖 / 评论 / 发悬赏时查敏感词 | 每次读 200 条 `wordfilters` | 读 1 个汇总文档 `wordlist/main`（**200 → 1**） |
| 首页一次加载 | 帖子 20 + 热榜 1 + 话题 200 + 配置 4 ≈ **225 次读 / 4 次调用** | 帖子 20 + 版本号 1 + 首次算热榜话题 60 ≈ **21–81 次读 / 2 次调用** |
| 首页 20 秒内重复进入 | 再读一遍 225 次 | 版本号没变 → **1 次读**（直接用本地缓存） |
| 管理后台每个操作 | 每次都查一次 `admin_sessions` | token 进程内缓存 60 秒，少 1 次读 |

怎么做到的：

1. **版本号**：`meta` 集合的 `meta/versions` 文档存 `{ content, ads, config }` 三个计数器；发帖/评论/点赞/删帖 → `content+1`，改广告 → `ads+1`，改公告/运营配置/词库 → `config+1`。
2. **首页合并请求**：`siteData` 云函数新增 `homeMeta` 动作，一次返回热榜、话题、公告、banner、广告；客户端 `fetchHomeMeta()` 带上上次的版本号，三个计数器都没变就直接用 `wx.setStorageSync('homeMeta')` 里的缓存（`unchanged: true`，服务端只读 1 次版本号）。
3. **词库单文档**：`wordlist/main` 保存 `[{id, word}]` 全量词表，`checkWords` 只读这一份；管理台加词/删词时后台自动重建这份文档，所以加词立刻生效（不再有分钟级延迟）。
4. **token 缓存**：`adminApi` 的 `resolveToken` 增加 60 秒内存缓存，管理台连续操作时不再每次回表。

实测（真实云环境 + 开发者工具）：

- 首页第一次：`unchanged:false`，只读了 7 条帖子就把热榜和话题算完；
- 20 秒内再进首页：`unchanged:true`，只花 1 次版本号读；
- 发帖后版本号自动 `content 3 → 4`，下次进首页自动刷新；
- 刚在管理台加的屏蔽词，立刻能拦住带词的帖子，`hits` 计数 +1。

> 备注：读次数只是计费的一部分（还有云函数调用次数、出网流量），但这三项是校园场景里数量级最大的浪费，收掉之后日常运营成本基本可以忽略。

## PC 端后台方案（下一步，M3）

现状：管理后台是小程序内的「管理台」（我的 → 管理台），适合圈主随手处理；要在电脑上批量操作，建议做一个独立网页后台。

技术选型（和现有架构兼容、不买服务器）：

- 前端：`Vue 3 + Vite + Element Plus`（表格/分页/弹窗都是现成的）
- 数据：`@cloudbase/js-sdk` 直接调用同一个 `adminApi` 云函数（手机端和网页端共用一套接口，不用重写业务）
- 部署：微信云开发「静态网站托管」，免费额度够用，域名都不用买
- 登录：网页端没有微信登录，方案是「管理员账号 + 密码」——新增 `adminLogin` 云函数（密码哈希存 `settings`，登录成功发一个随机 token 存 `admin_sessions`），`adminApi` 增加 token 校验；手机端继续用 openid 白名单

工作量：脚手架 + 登录 + 用户/帖子/举报/反馈/公告/配置/回收站/备份 9 个页面，约 1–2 天；先做「登录 + 举报 + 帖子」三页能跑通，再补齐其余页面。


## PC 端后台（Web）

手机端的「管理台」适合随手处理，批量操作（搜帖子、翻举报、封人）在电脑上更顺。网页后台与手机端共用同一个 `adminApi` 云函数：

| 页面 | 能做什么 |
|---|---|
| 登录 | 账号 `admin` + 密码（第一次是 `campus2026`），登录后拿 7 天有效的 token |
| 工作台 | 帖子/评论/用户/订单总数、待处理举报与反馈、回收站、敏感词数量 + 最近举报 |
| 举报处理 | 分页、看被举报内容与作者、忽略举报、删帖（进回收站） |
| 帖子管理 | 关键词搜索、分页、置顶/取消置顶、删除 |
| 用户管理 | 搜昵称、封禁（填原因）/解封、设/取消管理员（仅圈主） |
| 建议反馈 | 分页、标记已处理（发系统消息）、删除 |
| 公告管理 | 发/编辑/删除、置顶、上下架 |
| 运营配置 | banner 文案、公告开关、举报/反馈话术 + 改登录密码 + 操作日志 |
| 回收站 | 恢复/彻底删除已删内容 |
| 敏感词库 | 加词/删词（上限 200） |
| 数据备份 | 一键导出 20 个集合为 JSON、拿下载链接、删除备份 |

技术栈：Vue 3 + Vite + Element Plus + `@cloudbase/js-sdk`；鉴权用「账号密码换 token」（token 存 `admin_sessions`，7 天过期）。

目录：`admin/web/`，启动/构建/部署说明见 `admin/web/README.md`。

本地体验（不需要网络）：

```bash
cd admin/web
npm install
$env:VITE_MOCK='true'; npm run dev   # Windows PowerShell
```

连云开发：
1. 云开发控制台 → 环境 `cloud1` → 登录授权 → 打开「匿名登录」（网页端没有微信 openid）
2. `npm run build`，把 `dist/` 上传到 云开发 → 静态网站托管
3. 打开控制台给的网址，账号 `admin` / 密码 `campus2026`，登录后到「运营配置 → 修改登录密码」改掉

> 云函数 22 个（多了 `adminLogin`、`adminApi`），集合 24 个（含 `admin_sessions`、`admin_accounts`、`approvals`、`meta`、`wordlist`、`ads`、`backups`）。


### 管理后台的身份与权限（RBAC）

- 5 种身份：圈主 owner / 开发者 developer / 管理员 admin / 运营 operator / 数据分析员 analyst。
- 账号存在 `admin_accounts`，登录后 token 存在 `admin_sessions`（带角色，12 小时，剩余 6 小时滑动续期）。
- 开发者的修改类操作不会直接执行，会先生成 `approvals` 待审核，管理员/圈主点通过后由服务端重放执行。
- 运营可删帖/删评论/处理举报、管理公告与敏感词，并通过 `posts.trace` 追溯某条帖子的操作记录。
- 数据分析员只读，任何写操作都会被云函数拒绝。
- 网页「账号管理」「修改审核」分别只对圈主、圈主+管理员+开发者开放。
